# IUST LMS MCP

A local MCP server for the IUST Learning Management System (Moodle), with a separate direct-login flow for the IT service portal.

## LMS tools

- `check_lms_connection`: starts at the LMS login page, follows its identity-provider button through ITS, and checks for the direct credential form without submitting credentials.
- `get_lms_dashboard`: signs in through the LMS-generated OAuth request and returns the authenticated `/my/` page.
- `read_lms_page`: returns page text, links, and form field names from `lms.iust.ac.ir`; `max_chars` controls text output up to 200,000 characters.
- `submit_lms_form`: fetches fresh Moodle form tokens and submits a selected POST form.
- `request_lms`: sends authenticated GET, POST, PUT, PATCH, or DELETE requests to the LMS origin.

The LMS flow begins at `/login/index.php`, follows its identity-provider button to `/auth/oauth2/login.php`, authenticates at the ITS login page, and returns through the LMS OAuth callback to `/my/`. The server uses the callback and OAuth state generated by LMS instead of changing the ITS portal's separate redirect URI.

## IT portal tools

- `check_portal_connection`: checks that the ITS homepage OAuth bootstrap renders the direct credential form, without submitting credentials.
- `get_portal_dashboard`: signs in to ITS and lists service links.
- `read_portal_page`, `submit_portal_form`, `request_portal`: read and submit forms or same-origin requests on `its.iust.ac.ir`.

## Credentials and sessions

Copy `.env.example` to `.env`, then fill in `IUST_USERNAME` and `IUST_PASSWORD`. The `.env` file is ignored by Git. The server loads it at startup with Node's `--env-file` option. Cookies, form tokens, OAuth state, and authorization codes stay in memory; cookies are sent only to the host and path allowed by their cookie scope. Authenticated sessions are held in memory for up to ten minutes.

```bash
cp .env.example .env
# Edit .env with your IUST username and password
npm install
npm start
```

The server uses MCP over stdio, so standard output is reserved for MCP messages. Codex starts it with the same `.env` file:

```bash
codex mcp add iust-lms -- node --env-file=/absolute/path/to/iust-portal-mcp/.env /absolute/path/to/iust-portal-mcp/server.js
codex mcp list
```

Restart Codex if its tool list does not refresh.

## Scope

Page reads and data-changing requests are restricted to `https://lms.iust.ac.ir` or `https://its.iust.ac.ir`. The LMS login flow may navigate between those two hosts for OAuth. Other linked services are not accessed. Form submissions and non-GET requests can change course or account data; no write action was used during verification.
