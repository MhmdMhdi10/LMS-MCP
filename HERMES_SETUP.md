# Use the IUST LMS MCP with Hermes Agent

This guide connects Hermes Agent to this local MCP server over stdio. The server signs in to IUST LMS through the LMS-generated OAuth flow and keeps credentials and session cookies local.

## Current Hermes setup

Hermes is already configured on the machine where this project was set up:

- MCP name: `iust_lms`
- Hermes config: `~/.hermes/config.yaml`
- Transport: local stdio process
- Credential source: this project's `.env`, read by Node at process start
- Enabled in Hermes: the five LMS tools below
- Disabled in Hermes: the five separate ITS portal tools

The project `.env` is ignored by Git and should stay local. Do not copy `~/.hermes/config.yaml` into this repository; it can contain unrelated private settings.

## Install or repair the local setup

Run these commands from the project directory:

```bash
npm ci
if [ ! -f .env ]; then cp .env.example .env; fi
chmod 600 .env
```

Edit `.env` and set the two values:

```dotenv
IUST_USERNAME=your_iust_username
IUST_PASSWORD=your_iust_password
```

Do not paste the credentials into Hermes chat, `config.yaml`, shell command arguments, or Git. The MCP process reads `.env` directly through Node's `--env-file` option.

To register this server in Hermes, use an absolute Node path and absolute project paths. Run the following from the project directory:

```bash
PROJECT_DIR="$(pwd)"
NODE_BIN="$(command -v node)"
hermes mcp add iust_lms \
  --command "$NODE_BIN" \
  --connect-timeout 60 \
  --args \
  --env-file="$PROJECT_DIR/.env" \
  "$PROJECT_DIR/server.js"
```

`--args` must stay at the end because it consumes the remaining command-line arguments. Hermes stores the command and file paths in `~/.hermes/config.yaml`; credential values are not copied there.

If Hermes asks which tools to enable, expose the LMS tools and leave the ITS portal tools disabled. To change the selection later, run:

```bash
hermes mcp configure iust_lms
```

Keep these enabled:

- `check_lms_connection`
- `get_lms_dashboard`
- `read_lms_page`
- `submit_lms_form`
- `request_lms`

Leave these disabled for an LMS-only Hermes connection:

- `check_portal_connection`
- `get_portal_dashboard`
- `read_portal_page`
- `submit_portal_form`
- `request_portal`

## Confirm Hermes can use it

```bash
hermes mcp list
hermes mcp test iust_lms
hermes tools list --platform cli
```

`hermes mcp test` checks the stdio connection and discovers the server's tools. `hermes tools list --platform cli` shows the tools Hermes actually exposes after filtering. A successful MCP handshake does not sign in to LMS; the first dashboard or page call performs authentication.

If Hermes is already open, start a new session or run `/reload-mcp` in the session. Existing sessions do not automatically receive a changed tool list.

## Ask Hermes to use LMS

Example requests:

```text
Use iust_lms to sign in and summarize my LMS dashboard.
Use iust_lms to read the page at /my/ and return the course links it can see.
Use iust_lms to inspect this LMS form and explain what it would submit. Do not submit it yet.
```

The first authenticated LMS call follows the OAuth flow generated by `lms.iust.ac.ir`, uses the ITS login form, and returns to LMS. Credentials are sent only to the IUST login host. Cookies, form tokens, OAuth state, and authorization codes stay in MCP process memory; authenticated sessions are cached for up to ten minutes.

## Tools and access

| Tool | Use |
| --- | --- |
| `check_lms_connection` | Check the LMS login/OAuth route without submitting credentials. |
| `get_lms_dashboard` | Authenticate through the LMS OAuth flow and read the dashboard. |
| `read_lms_page` | Read page text, links, and form field names from LMS. |
| `submit_lms_form` | Submit a Moodle form using fresh hidden form tokens. This can change LMS data. |
| `request_lms` | Make an authenticated GET, POST, PUT, PATCH, or DELETE request on the LMS host. Non-GET methods can change data. |

The Hermes configuration allows the five LMS tools, including full LMS read and write access. Write operations can affect course or account data; ask Hermes to inspect the target and describe the change before submitting a form or sending a non-GET request.

The server restricts LMS requests to `https://lms.iust.ac.ir`. Its separate ITS tools are filtered out in the current Hermes configuration. The Moodle dashboard can load course cards dynamically with JavaScript, so a plain HTTP page read may not include every course card; use a rendered browser view or an LMS endpoint when that happens.

## Troubleshooting

- **`Connection closed` or no tools discovered:** run `npm ci` from the project directory and make sure the configured Node path exists. Hermes needs the project dependencies in `node_modules/`.
- **Credentials missing:** check that `.env` exists in the project directory and contains both `IUST_USERNAME` and `IUST_PASSWORD`; restart/reload the MCP after changing it.
- **Login fails:** verify the credentials by signing in to IUST in a browser, then retry `get_lms_dashboard`. The MCP follows the LMS OAuth flow and should not use a manually copied session cookie.
- **Tools do not appear in an open Hermes session:** start a new session or run `/reload-mcp`.
- **Tool is absent from Hermes:** run `hermes mcp configure iust_lms` and enable the corresponding LMS tool.
